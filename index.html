1. Introduction to File Organization

What is a File?

File: A collection of data placed under secondary or non-volatile storage (e.g., hard drive, SSD, tape).

Data Structures vs File Structures

Aspect Data Structures File Structures
Location Main memory (RAM) Secondary storage (disk)
Speed Fast (~120 nanoseconds) Slow (~30 milliseconds)
Persistence Volatile (lost on power off) Non-volatile (persistent)
Size Small, expensive Large, cheap
Memory vs Disk Speed Analogy:
  • Looking at book index: 20 seconds
  • Going to library: 54 days
  • RAM is ~100,000 times faster than disk!

File Structure Types

Logical Structure

How programmers see the file

  • Text files
  • Image files
  • Data files

Physical Structure

How file is stored on disk

  • Tracks and sectors
  • Blocks
  • Cylinders

File Organization Goals

  1. Fast Access Time: Minimize disk trips
  2. Good Space Utilization: Reduce wasted space
  3. Efficient Data Retrieval: Get what you need in one access

2. File Operations & C# Programming

Physical vs Logical Files

Physical File: Collection of bytes on disk, known by OS, appears in file directory

Logical File: Channel/object in program that links to physical file

Opening Files in C#:
FileStream myFile = new FileStream("sample.txt", FileMode.Open, FileAccess.Read); StreamReader reader = new StreamReader(myFile);

File Modes (MEMORIZE!)

Mode Description File Exists? File Doesn't Exist?
Open Opens existing file ✅ Opens ❌ Error
Create Creates new file ⚠️ Deletes & recreates ✅ Creates new
CreateNew Creates only if doesn't exist ❌ Error ✅ Creates new
Append Adds to end ✅ Adds to end ✅ Creates & adds
Truncate Deletes contents ✅ Empties file ❌ Error
OpenOrCreate Opens or creates ✅ Opens ✅ Creates

File Access Types

Access Can Read? Can Write?
FileAccess.Read ✅ ❌
FileAccess.Write ❌ ✅
FileAccess.ReadWrite ✅ ✅

Seek Operations (HIGH EXAM PROBABILITY!)

Seek Syntax:
myfile.Seek(offset, SeekOrigin);

SeekOrigin Values:

  • SeekOrigin.Begin: From start of file
  • SeekOrigin.Current: From current position
  • SeekOrigin.End: From end of file

Common Exam Questions:

1 myfile.Seek(10, SeekOrigin.Begin);
→ Moves to byte 10 from start
2 myfile.Seek(5, SeekOrigin.End);
→ Moves 5 bytes AFTER end (invalid for reading)
3 myfile.Seek(-10, SeekOrigin.Current);
→ Moves 10 bytes backward from current position
4 myfile.Seek(0, SeekOrigin.End);
→ Moves to last byte in file

3. Field & Record Organization

Basic Definitions

File: Collection of records

Record: Collection of related fields

Field: Smallest logically meaningful unit of information

Key: Field(s) used to identify a record

  • Primary Key: Uniquely identifies a record (e.g., ISBN, ID)
  • Secondary Key: Non-unique, used for searching (e.g., Author, Department)

Field Organization Methods

Method Advantages Disadvantages Example
1. Fixed Length Easy to read/write
Fast access		 Wastes space with padding ID: 5 chars, Name: 20 chars
2. Length Indicator Easy to jump to end
Less waste		 Max 255 bytes (1 byte length)
Extra bytes needed		 05AHMED (5 = length)
3. Delimiters May waste less space
Flexible		 Must check every byte
Delimiter can't appear in data		 AHMED|MOHAMED|CS
4. Keyword=Value Self-describing
Missing fields allowed		 Wastes space with keywords ID=123|NAME=AHMED

Record Organization Types

Fixed-Length Records

  • All records same size
  • Can use RRN (Relative Record Number)
  • Direct access possible
  • Formula: Byte offset = RRN × Record Length

Variable-Length Records

  • Records vary in size
  • Cannot use RRN
  • Must use byte offset
  • Requires index or sequential search
Direct Access Calculation:

Given: RRN = 30, Record Length = 101 bytes

Byte Offset = 30 × 101 = 3030 bytes

Then use: myfile.Seek(3030, SeekOrigin.Begin);

4. Reclaiming Space in Files

⚠️ THIS IS THE MOST IMPORTANT EXAM TOPIC! ⚠️

Questions 2 and parts of Question 5 in both 2024 and 2025 finals focused heavily on this topic.

Deletion Strategies

1. Record Deletion & Storage Compaction

  • Mark record as deleted (e.g., place '*' at beginning)
  • Space not immediately released
  • Later: run compaction program to squeeze file
  • Disadvantage: Wasted space until compaction

2. Dynamic Space Reclamation with AVAIL LIST

AVAIL LIST: A linked list (stack) of available deleted records

  • Header record stores beginning of list (-1 = empty)
  • When record deleted: marked and added to AVAIL LIST
  • When record added: use space from AVAIL LIST

Placement Strategies (CRITICAL FOR EXAMS!)

Strategy List Sorting Selection Method Best For
First-Fit Not sorted First record large enough Fast insertion, simple
Best-Fit Ascending by size Smallest record that fits Minimize internal fragmentation
Worst-Fit Descending by size Largest record available Minimize external fragmentation

Placement Strategy Example (COMMON EXAM QUESTION):

Given AVAIL LIST: size=60, size=50, size=22, size=10

Record to add: size=20

1 First-Fit: Uses size=60 (first one that fits)
2 Best-Fit (sorted: 10,22,50,60): Uses size=22 (smallest that fits)
3 Worst-Fit (sorted: 60,50,22,10): Uses size=60 (largest)

Fragmentation Types

Type Location Cause Example
Internal Fragmentation Inside records Record smaller than allocated space Record size=20, space=29
→ 9 bytes wasted
External Fragmentation Between records (in AVAIL LIST) Space too small to reuse Remaining space=5 bytes
(too small for any record)

Fixed-Length Record AVAIL LIST (Stack Implementation)

Initial File: A, B, C, D, E (RRN: 0-4)

1 Delete RRN=2:
File: A, B, *-1, D, E
List head → 2
2 Delete RRN=4:
File: A, B, *-1, D, *2
List head → 4 (points to 2, which points to -1)
3 Add record F:
File: A, B, *-1, D, F
List head → 2 (F takes RRN=4)

Variable-Length Record AVAIL LIST

Format in deleted record: *NextAddress|Size|

Example: *-1|50| means: size=50, no next record (-1)

Key Differences from Fixed-Length:
  • Store size in deleted record
  • Use byte offset instead of RRN
  • Check if new record fits in available space
  • Handle leftover space (internal/external fragmentation)

5. Binary Search & Indexing

Sequential vs Binary Search

Aspect Sequential Search Binary Search
Time Complexity O(n) O(log₂ n)
Average Reads n/2 records 1 + log₂ n records
For 2000 records ~1000 reads ~11 reads
Requirement No sorting needed File must be sorted
Record Type Any Fixed-length only

Indexing Concepts

Index: A tool for finding records quickly - consists of key field + reference (address/RRN)

Benefits of Indexing:

  • Impose order without rearranging file
  • Multiple access paths (multiple indexes)
  • Works with variable-length records
  • Index file is much smaller than data file
  • Can keep index in RAM for fast binary search

Index Types

Primary Index

  • Built on primary key field
  • Unique entries (1-to-1)
  • Example: Course Code → Address

Secondary Index

  • Built on secondary key field
  • Non-unique (1-to-many)
  • Example: Department → List of Courses

Index Operations (Question 5 in 2024/2025 Exams):

  1. Create: Build empty index and data files
  2. Load: Read index into memory
  3. Rewrite: Write index back to disk
  4. Add: Append data file, insert in index (sorted)
  5. Delete: Remove from index, mark in data file
  6. Update: Modify data file, update index if key changed

Using Multiple Indexes for Queries

Example Query: Find all second-year computer science courses in first semester

1 Search Department Index for "Computer Science" → List A
2 Search Class Index for "2" → List B
3 Search Semester Index for "1" → List C
4 Perform logical AND: List A ∩ List B ∩ List C → Final Result

6. Blocking & Buffering

Key Concepts

Blocking: Grouping multiple records into fixed-size blocks to reduce I/O operations

Buffering: Using memory buffers as intermediaries between CPU and storage

Blocking

I/O Operations Formula:

Number of I/O operations = ⌈Records / Block Size⌉
Example (COMMON EXAM QUESTION):

10,000 records with block size of 200 records:

I/O operations = ⌈10,000 / 200⌉ = 50
Aspect Advantages Disadvantages
Blocking • Reduces I/O overhead
• Efficient for sequential access
• Better performance		 • Uses memory space
• Latency for small reads/writes

Buffering Types

Feature Single Buffering Double Buffering
Memory One buffer Two buffers
Performance Limited parallelism
CPU or I/O may be idle		 Overlaps CPU and I/O
Minimizes idle time
Implementation Simple More complex
Applications Small-scale systems Real-time, high-performance systems
Operation I/O fills buffer
→ CPU processes
→ Repeat		 I/O fills Buffer 1
CPU processes Buffer 2
(simultaneous)

True/False Questions (From 2025 Exam):

  1. Single buffering is more complex than double buffering. → FALSE
  2. Double buffering requires two buffers, allowing overlap between CPU and I/O. → TRUE
  3. Blocking minimizes I/O overhead by grouping records into smaller chunks. → FALSE (larger chunks, not smaller)

Blocking vs Buffering Comparison

Feature Blocking Buffering
Focus Grouping multiple records Temporary storage in memory
Primary Use Reducing I/O frequency Bridging speed differences
Memory Use Uses memory for blocks (larger) Uses smaller memory buffers
Complexity Relatively simple Can be complex (double buffering)

7. Disk Storage (HDD vs SSD)

Hard Disk Drive (HDD) Organization

Components:

  • Platter: Circular disk where data is stored
  • Track: Concentric circle on platter surface
  • Sector: Smallest addressable portion (typically 512 bytes)
  • Cylinder: Set of tracks directly above/below each other
  • Cluster: Fixed number of contiguous sectors
  • Extent: Group of contiguous clusters

Disk Capacity Formulas (MEMORIZE!)

Track Capacity = Sectors per Track × Bytes per Sector
Cylinder Capacity = Number of Surfaces × Track Capacity
Disk Capacity = Number of Cylinders × Cylinder Capacity

Example Problem:

Given: 80 tracks/surface, 100 sectors/track, 512 bytes/sector, 2 surfaces

1 Track Capacity = 100 × 512 = 51,200 bytes = 50 KB
2 Cylinder Capacity = 2 × 50 = 100 KB
3 Disk Capacity = 80 × 100 = 8,000 KB

HDD Access Time Components

  1. Seek Time: Move arm to correct cylinder
  2. Rotational Delay (Latency): Wait for sector to rotate under head
  3. Transfer Time: Time to read/write data
Transfer Time = (Bytes Transferred / Bytes on Track) × Rotation Time

HDD vs SSD Comparison (CRITICAL FOR EXAMS!)

Feature HDD SSD
Full Form Hard Disk Drive Solid State Drive
Movement Spinning platters + moving arm No moving parts
Speed Slower (~80 MB/s) Faster (~500 MB/s)
Latency High (seek + rotation) Low (instant access)
Storage Capacity 250 GB - 14 TB 120 GB - 4 TB
Read/Write Time Longer Shorter
Weight Heavier Lighter
Power Consumption Higher (spinning) Lower
Cost Cheaper More expensive
Size Larger Smaller
Reliability Less reliable (mechanical failure) More reliable
Access Type Sequential and random Instant random access
Fragmentation Impact Significant (needs defrag) Irrelevant
Best For Large storage, archival, backups OS, applications, real-time processing

Real-World Comparison (Common Exam Questions):

Scenario HDD SSD
Booting OS 30-40 seconds 10-15 seconds
1 GB File Transfer ~15 seconds (80 MB/s) ~2 seconds (500 MB/s)
Gaming (Level Load) Longer load times Near-instant loading

8. Hashing

Core Concepts

Hash Function: h(k) transforms a key into an address

Home Address: The address computed by hash function for a key

Collision: Two different keys map to the same address

Synonyms: Keys that hash to the same address

Bucket: Logical storage unit for records with same hash value

Time Complexity Comparison

Method Time Complexity Notes
Simple Index (Binary Search) O(log₂ N) Good for sorted data
B-Trees / B+ Trees O(log_k N) Better than binary search
Hashing O(1) Best average case!

Hash Function Examples

Common Hash Function Structure:

int hash(string key) { int h; h = 2*key[0] + 3*key[1] + 6*key[2]; return (h mod 13); }

Example Problem (FROM 2025 EXAM):

Given: ASCII(O)=79, ASCII(W)=119, ASCII(L)=76

Find h("Owl") and h("Low"):

1 h("Owl") = (2×79 + 3×119 + 6×108) mod 13
= (158 + 357 + 648) mod 13
= 1163 mod 13 = 6
2 h("Low") = (2×76 + 3×111 + 6×119) mod 13
= (152 + 333 + 714) mod 13
= 1199 mod 13 = 4

Collision Resolution: Progressive Overflow

Insertion Algorithm:

  1. Go to home address h(k)
  2. If free, place key there
  3. If occupied, try next position
  4. Wrap around if reach end (last → 0)
  5. Continue until empty position found

Search Algorithm:

  1. Go to home address h(k)
  2. If key found, done
  3. If empty, key not in table
  4. Otherwise try next position
  5. Stop when: found, empty, or back to home

Progressive Overflow Example (VERY COMMON IN EXAMS):

Given: Hash function: key mod 11

Keys: 37, 48, 4, 15, 26, 125, 39, 6

Average Search Length = (1+2+3+4+5+6+5+6) / 8 = 32/8 = 4

Search Length Calculation

Search Length: Number of accesses required to retrieve a record

Average Search Length = (Sum of all search lengths) / (Number of records)

9. Common Exam Patterns & Tips

Question 1: True/False & Operations (10 points)

Part A: True/False Statements

  • Focus on: Buffering, Blocking, Fragmentation, RRN usage
  • Common tricks: "minimize" vs "maximize", "smaller" vs "larger"
  • Always correct FALSE statements!

Part B: File Operations

  • Seek operations: Know all three SeekOrigin types
  • FileMode: Memorize all 6 modes and their behaviors
  • FileAccess: Know Read/Write/ReadWrite differences

Question 2: Placement Strategies (10 points)

ALWAYS APPEARS IN EXAMS!

What to Expect:

  1. Explain First-fit, Best-fit, Worst-fit
  2. Which strategy minimizes search? Answer: First-fit
  3. Given file with records + AVAIL LIST:
    • Delete records → Update AVAIL LIST
    • Add records → Use placement strategy
    • Show final AVAIL LIST state

Step-by-Step Approach:

1 Draw initial file with sizes and addresses
2 For deletions: Mark as deleted, add to AVAIL LIST (stack)
3 For insertions: Apply placement strategy, check fit
4 Update AVAIL LIST after each operation
5 Show final AVAIL LIST with sizes

Question 3: Blocking & Buffering (10 points)

  1. Difference between Block and Buffering
    • Block: Grouping records
    • Buffering: Memory intermediary
  2. 3 Advantages & 3 Disadvantages (for each: Block, Single Buffer, Double Buffer)
  3. HDD vs SSD differences (See comparison table above)
  4. I/O Operations calculation: Use formula ⌈Records / Block Size⌉

Question 4: Hashing (15 points)

  1. Define: Hash function, Home address, Collision
  2. Ways to reduce collisions:
    • Good hash function (uniform distribution)
    • Larger address space
    • Prime number modulus
  3. Progressive Overflow steps (See algorithm above)
  4. Calculate hash values (Given ASCII codes)
  5. Draw hash table + Calculate search lengths
    • Insert keys using progressive overflow
    • Calculate search length for each
    • Compute average search length

Question 5: Indexing (15 points)

Most Complex Question!

  1. Operations to maintain indexed file:
    • Create, Load, Rewrite, Add, Delete, Update
  2. Design indexing system:
    • Identify primary key (unique field)
    • Identify secondary keys (non-unique searchable fields)
    • Build primary index (key → address)
    • Build secondary indexes (secondary key → list of primary keys)
    • Use indexes to answer queries (logical AND for multiple conditions)

Example Table Structure:

Course Code Department Class Semester
323311
211211

Primary Index: Course Code → Address (sorted by key)

Secondary Indexes: Department, Class, Semester → Course Codes

Final Exam Tips

  • Time Management: 120 minutes for 60 points = 2 min/point
  • Question Priority: Q1 & Q4 are usually fastest → do first
  • Show Your Work: Especially for Q2 (AVAIL LIST), Q4 (search length), Q5 (indexes)
  • Draw Diagrams: Visual representation earns partial credit
  • Check Formulas: Disk capacity, I/O operations, search length
  • Review Past Papers: Questions repeat with different numbers!
